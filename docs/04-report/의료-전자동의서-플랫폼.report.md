## 1. 개요

ModuSign 벤치마크에서 출발해, 자체개발 HIS **Hospital RUN**(NestJS/Next.js/Prisma)의 **mock 전자서명**(검증=`sha256(value)`, 실 키쌍/CA/TSA/HSM 부재)을 대체하는 **독립 전자서명 트러스트 서비스 `sign`** 을 설계·구현했다. 자체 PKI(2단 CA)+RFC3161 TSA+PAdES-LTA로 법적 무결성을 제공하고, Hospital RUN과 API/Webhook/SSO로 연동한다.

**기관 성격**: 민간 의료법인 재단 → KCMVP 비강제(표준 알고리즘), EMR 인증제 대상(기능성·상호운용성·보안성 반영).

## 4. 동작하는 핵심 기능 (실서버 검증)

```
발급(enroll) → 서명요청(멱등) → [본인확인 강결합] → 다채널 순차서명(환자앱 + 의료진 SSO, 순서게이팅)
→ 실 PKI 서명 + TSA + LTV 봉인 → 검증(공개키 실검증 + 폐기 + LTV) → 폐기(CRL/OCSP) → 감사(해시체인)
→ Webhook(HMAC) → API 인증(ConsumerApp) → durable 저장(file/Prisma 교체축)
```

**mock 대비 핵심 개선**: 검증이 `sha256(value)` → **공개키 `crypto.verify(실서명)`**. 인증서 만료 무관 **LTV 장기검증**. 키 **AES-256-GCM 격리**(SOFT→HSM 추상화).

## 9. 결론

**의료 전자서명 트러스트 서비스가 설계→구현→표준화→HIS 라이브 연동→운영준비까지 완주**했다. 실 PKI(2단 CA·실 X.509)·**실 CMS(CAdES-BES)·PAdES PDF·RFC3161**·LTV·폐기(CRL/OCSP)·본인확인 강결합·감사 TSA앵커·API인증·시크릿회전·durable 저장이 모두 실서버 e2e로 검증됐고, **HIS와 OIDC 라이브 교차검증** 및 점진전환(signProvider 토글) 합의·문서화까지 완료했다.

추가로 이번 세션에 **Prisma 라이브를 실 PostgreSQL로 실행 검증**(JSONB 키순서 무결성 버그 발견·수정), **개인키를 crypto-proxy로 분리**(앱 키 미보유)하고 **AWS KMS 클라우드 HSM 어댑터를 실구현**(개발은 SOFT로 진행, 운영은 자격증명만 주입), **CA/TSA 키 재기동 영속·Issuing 회전**을 완료했다. 또한 프로젝트의 핵심인 **환자·동의서 서비스**를 직접 커버하도록 보강했다 — 환자 본인인증 프록시 분리(개발=mock, 운영=PASS/명의 드롭인), 토큰 기반 환자 서명 웹플로우(열람→본인확인→서명, 원외 fallback), 발송(알림톡/SMS)·동의 철회·기한 만료까지 흐름을 완성했다(Inc14~16, e2e 검증). HIS 환자앱이 정식 UX인 분담은 유지하되 sign이 트러스트 게이트와 fallback을 직접 제공한다.

나아가 이번 마일스톤에서 **실서버 배포(`https://sign.example.org`, TLS·재기동 내성)**, **정식 프론트 SPA(환자 포털+관리자 콘솔)**, **HIS·PACS 연동 완결**(키·SSO[aud=sign 강제·sub 바인딩]·Webhook·문서 + 통합 결정 #6 병행·#7 위험도별 본인확인 확정), **보안 리뷰 + Critical(C1 무인증 서명 위조) 차단**까지 마쳤다. HIS는 코드·결정 완료, PACS는 양 플로우 구현 완료로 **양 팀 모두 통합 준비 완료** 상태다.

게이트 해제의 **잔여는 (1) `sign.mode=EXTERNAL` P1 공동 게이트(일정 합의), (2) 운영 환경/계약 의존분(실 PASS·알림톡·KMS 자격증명, mTLS, 관리자 IP제한 등 go-live 하드닝)** 뿐이며, sign 단독 개발 범위는 사실상 완료됐다. 어댑터·프록시·가이드·문서가 모두 준비되어 자격증명 주입과 일정 합의만 남았다. 다음 단계는 HIS와 **P1 파일럿(동의서 1종 EXTERNAL)** 실시다.
