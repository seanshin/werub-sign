# 전자계약 메뉴·UI 기획서

- 상태: v0.4 (as-built — U1~U5 전 단계 + 후속 화면 §6 완결. v1.11~v1.14 반영)
- 작성: 2026-07-06 · 최종 갱신: 2026-07-28
- 관련: `general-contracts.design.md`(기능 설계 v1.1 as-built), 모두싸인 기능 분석
- 목적: 일반 전자계약 기능을 콘솔에서 **"전자계약" 단일 섹션**으로 묶어, 준비→발송→체결→관리 업무 흐름이 메뉴 구조에 그대로 드러나게 한다.

## 1. 현재 상태 (P1~P3 구현분)

| 구분 | 현재 | 문제 |
|---|---|---|
| 사이드바 | "전자계약" 섹션 — 계약함·새 계약 2개 | 발송·교부·알림 기능이 메뉴에 드러나지 않음 |
| 계약함 | 상태 탭·검색·라벨 표시·CSV | 라벨 **필터** 없음(표시만). 현황 요약이 메인 대시보드 위젯에만 있음 |
| 상세 | 서명자·문서·검증 탭 + 발송/독촉/내부서명/교부 재발급 | 계약 감사 이력(`contract:<id>` 스트림)이 건수만 노출되고 **뷰어 없음** |
| 새 계약 | PDF·서명자·접근암호 | 프리셋(자주 쓰는 구성) 없음 — 반복 입력 |
| 발송·리마인더 | 자동(스케줄러)+수동 독촉 | 리마인더 정책(주기·상태)을 콘솔에서 볼 수 없음. 발송이력은 공용 "발송 이력" 화면에 섞여 있음 |
| 교부 | 자동+상세에서 재발급 | 교부 이력(누가 언제 받았는지)이 상세에 정리돼 있지 않음 |
| 메뉴 노출 | 플래그 OFF여도 메뉴 표시 → 화면에서 "비활성" 안내 | 미활성 기간엔 헛메뉴 |

## 2. 정보구조(IA) — 사이드바 "전자계약" 섹션 (v0.3 as-built)

```
전자계약                        ← 섹션명 유지(사용자 확정)
 ├─ 계약 현황                   ← 구현: 현황 카드 + 처리 필요 목록(랜딩, operator 기본 랜딩)
 ├─ 계약함                      ← 구현: 탭(+보관됨)·검색·라벨/카테고리 칩 필터·현재 단계 컬럼
 ├─ 새 계약                     ← 구현: 업로드 PDF 배치 편집(스탬프)·순차/동시·내부 알림이메일
 ├─ 계약 서식                   ← 후속 구현: 내장 36종+커스텀 갤러리 → 에디터(리치·배치·미리보기)
 ├─ 카테고리 관리               ← 후속 구현: 카테고리별 체결/전체 집계 → 계약함 필터 이동
 ├─ 주소록                      ← 후속 구현: 발송 상대방 CRUD·검색·발송 자동 학습
 └─ 알림·리마인더               ← 구현: 계약 발송이력 + 자동 리마인더 정책·수동 실행
```

- **역할**: admin·operator (viewer 는 계약함·현황 읽기만).
- **노출 정책**: `GENERAL_CONTRACTS` OFF 시 섹션 전체 **자동 숨김** — AdminLayout 이 `GET /v1/contracts/stats` 1회 프로브(404=숨김). 활성화하면 재배포 없이 메뉴 자동 등장(대시보드 위젯과 동일 원리). 전자결재(비활성=숨김) 관례와 일치.
- 콘솔 메인(서명요청 대시보드)의 "전자계약 진행" 위젯 클릭 → **계약 현황**으로 랜딩(현재는 계약함).

## 3. 화면별 기획

### 3.1 계약 현황 (`/admin/contracts/overview`) — 신설
계약 업무의 랜딩. "오늘 처리할 것"이 먼저 보인다.
- **현황 카드 4**: 진행 중(서명 대기) · 체결 완료 · 만료 임박(7일 이내) · 이번 달 체결 건수
- **처리 필요 목록**(우선순위순):
  - 내 서명 차례(현재 단계=내부·지정자=로그인 계정) → [내부 서명] 바로가기
  - 발송 대기(작성 상태 + 문서 업로드됨 + 미발송) → [발송]
  - 만료 임박(D-7) 미서명 → [독촉]
- **최근 활동**: 계약 감사 스트림 최신 10건(체결·발송·unlock 실패 등)
- 데이터: `stats` + `list`(status·기간 필터) + (P4) `GET /v1/contracts/activity` 통합 스트림

### 3.2 계약함 (`/admin/contracts`) — 보강
- 유지: 상태 탭(전체/서명중/작성/체결완료)·검색·CSV·페이지네이션·🔒 배지
- 보강:
  - **라벨 필터**(칩 클릭 → `?label=`, 백엔드 목록 필터 추가)
  - **기간 필터**(from/to — 백엔드 이미 지원, UI 미배선)
  - 행에 "현재 단계"(n차·내부/외부) 컬럼 — 누구 차례인지 목록에서 식별
- 빈 상태: "새 계약으로 시작" CTA 유지

### 3.3 새 계약 (`/admin/contracts/new`) — 보강
- 유지: PDF 선택→SHA-256 자동계산→생성 직후 원본 자동 업로드, 내부/외부 서명자 다단, 접근암호, 라벨
- 보강(P4):
  - **프리셋(요청 템플릿)**: 자주 쓰는 구성(제목 패턴·서명자열·라벨·접근암호 여부) 저장/불러오기 — 문서 서식이 아닌 "요청 구성" 저장(설계 원칙 유지)
  - 생성 완료 후 "바로 발송" 선택지(생성→발송 2클릭을 1플로우로)

### 3.4 계약 상세 (`/admin/contracts/[id]`) — 보강
- 유지: 헤더(상태·발송/독촉/내부서명/교부 재발급)·서명자·문서 뷰어·검증 탭
- 보강:
  - **이력 탭 신설**: `contract:<id>` 감사 스트림 뷰어(생성·발송·독촉·만료경고·unlock 성공/실패·서명·교부, LogDetail·무결성 배지·CSV — 전자결재 인증로그 뷰어 패턴 재사용). 백엔드 EP `GET /v1/contracts/:id/log` 신설 필요
  - **교부 카드**(체결완료 시): 마지막 교부 시각·링크 만료·[재발급] — 현재 재발급 결과 Modal 을 이력과 함께 정리
  - 진행 타임라인(1차→n차 시각 표시)

### 3.5 알림·리마인더 (`/admin/contracts/notifications`) — 신설
- **자동 리마인더 정책 카드**: 독촉 주기(`CONTRACT_REMIND_AFTER_DAYS`)·만료 경고(24h)·스케줄러 주기 — 읽기 표시(ops-status 연계) + [지금 실행](수동 auto-remind, 결과 토스트)
- **계약 발송이력**: 공용 발송이력에서 계약(EMAIL 채널·[교부] 포함)만 필터한 뷰 — 시각·계약·수신(마스킹)·종류(발송/독촉/만료경고/교부)·결과
- SMTP 상태(설정됨/mock) 표시 — 연동 설정 바로가기

### 3.6 교부 페이지 (`/contracts/delivery/[token]`, 공개) — 유지
- 현행 유지(제목·완료 PDF·감사추적인증서·만료 안내). 후속: 기관명/브랜딩 표시(연동 설정의 기관명 재사용)

## 4. 구현 단계

| 단계 | 내용 | 규모 |
|---|---|---|
| **U1 (즉시)** | **플래그 연동 자동 숨김**(stats 프로브)·계약함 기간/라벨 필터·현재 단계 컬럼 | 소 |
| **U2** | **계약 현황** 화면(카드+처리 필요 목록)·위젯 랜딩 변경 | 중 |
| **U3** | 상세 **이력 탭**(백엔드 `GET /v1/contracts/:id/log` + 뷰어)·교부 카드 | 중 |
| **U4** | **알림·리마인더** 화면(정책 카드·계약 발송이력·수동 실행) | 중 |
| **U5 (P4 연계)** | 프리셋(요청 템플릿)·생성→발송 원플로우·타임라인 | 중 |

각 단계 완료 기준: UI e2e + a11y(axe) 편입, 백엔드 EP 추가 시 e2e 게이트 편입, 매뉴얼은 활성화 시점 일괄 갱신.

> **구현 현황(2026-07-27)**: U1~U4 완료(v1.9.0 릴리즈 편입), **U5 완료(v1.12.0)** — 프리셋(기관 공용·접근암호 값 미저장·동일 이름 upsert)·'생성 후 바로 발송' 원플로우·상세 진행 타임라인(감사 스트림 기반). §1 표의 문제 항목 전부 해소. **본 기획서 전 단계 구현 완결.**
