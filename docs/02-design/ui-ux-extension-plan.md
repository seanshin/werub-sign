| i18n / 다크모드 | ❌ 없음 | 한국어 전용·Light only |

### 0.2 코드 검증으로 정정된 사실 (rev1 추정 → rev2 확정)
- **SSE/실시간: 백엔드에 전혀 없음**(`grep text/event-stream|@Sse|EventSource` = 0). rev1의 "백엔드 SSE 설계 존재"는 부정확 → 실시간은 **완전 신규**.
- **CSV 내보내기: 없음**. `requests.controller`의 유일한 `Content-Disposition`은 **감사인증서 PDF**(`audit-certificate.pdf`, `requests.controller.ts:142-143`)뿐 → CSV는 **완전 신규**.
- **환자 서명 입력: 본인확인 + 암호(PKI/CMS) 서명만**. **그린(handwritten) 서명 이미지/서명패드 없음**(`portal/[token]/page.tsx`는 identity 폼만, 서명값은 crypto). → 시각적 서명 표식은 별도 항목(§3-5).
- **문서 바이트: sign 미보유**(facade/createRequest는 `documentHash`만 수신). 포털은 `documentHashPrefix`(앞 12자)만 표시(`portal/[token]/page.tsx:478-483`) → PDF 미리보기는 문서 전달 경로 신설 필요.
- **정확 경로**(rev1 일부 오기 정정): 로그인 `POST /v1/auth/login`, 운영상태 `GET /v1/admin/ops-status`, readiness `GET /health/ready`, 목록 `GET /v1/requests`·`/v1/certificates`(이미 `{data,page}` + 푸시다운).

**결론**: 코어 UX는 견고. 확장 여지는 ①포털 법적·포용성, ②운영/심사 효율, ③접근성·테마·국제화 순. 아래는 가치 기준 우선순위 + **항목별 구현 명세·수용기준·하위작업·리스크**.

## 1. P0 — 법적효력·심사 직결 (필수)

### P0-1. 환자 포털 문서 미리보기 (PDF 뷰어) — 최우선
**근거**: 환자가 서명 대상을 보지 못하고(`documentHashPrefix`만) 서명 → 전자서명법·민법 "서명 대상 인지", 환자 알권리 리스크.

**설계 결정(기획 선행)** — 문서 바이트 확보 방식 택1:
- **(A·권장) caller 업로드형**: 요청 생성 시 caller(HIS/PACS/ERP)가 서명 대상 PDF를 sign에 업로드. sign이 저장 시 `SHA-256 == documentHash` 검증(불일치=거부, 위변조 차단). 포털 토큰으로만 열람.
- **(B) 무보관 URL 프록시형**: caller가 단기 서명 URL 제공 → 포털이 그 URL을 로드(sign 무보관). CORS·URL 만료·해시검증 caller 책임.
- **트레이드오프**: A=강한 무결성·일관 UX, 단 **sign이 PHI(원본 PDF) 보관** → 현 "해시만 보유" 원칙 변경, 보관·암호화(AES-256-GCM)·파기(요청 만료 시)·접근통제 정책 필요. B=무보관 유지, 단 표시 문서와 서명 해시 일치 보증 약함.

**구현 명세(A 기준)**:
- 백엔드: `POST /v1/requests`(+facade)에 `documentUpload`(multipart 또는 base64) 옵션 + 저장소 바이너리 슬롯(암호화) + `GET /v1/portal/:token/document`(토큰 게이트·`Content-Type: application/pdf`·`inline`, 해시 재검증). 요청 만료/완료 시 파기 배치 연계.
- 프론트: `react-pdf`(pdf.js) 뷰어를 `info`/`identity` 단계에 삽입 — 첫 페이지 우선 렌더·페이지 넘김·핀치/버튼 확대·다운로드. 로딩 skeleton.
- **수용 기준**: 포털에서 실제 PDF 렌더, 표시 PDF 해시 == `documentHash`, 토큰 없으면 401, 만료 후 파기 확인, 모바일 핀치줌.
- **하위작업/규모**: 설계결정(S) → 백엔드 저장/EP/암호화/파기(M) → 뷰어 통합(M) = **L**.
- **리스크**: PHI 보관 범위 확대(A) → 보안검토 필수. 대용량 PDF 스트리밍·메모리. 스캔 PDF(이미지)도 렌더 확인.

### P0-2. 목록 내보내기(CSV) + 심사 증빙
**근거**: EMR 인증(F008 접속기록)·ISMS-P(2.9 로그)·개인정보 안전성 심사 시 서명활동·발급이력·발송·감사를 내보내 제출/보존. 현재 내보내기는 감사인증서 PDF(요청 단위)뿐.

**구현 명세**:
- 백엔드: 스트리밍 CSV EP(페이지네이션 우회, 동일 필터 재사용) —
  - `GET /v1/requests/export.csv?q&status&from&to&days` (scope requests:write, 하드닝 시 인증)
  - `GET /v1/certificates/export.csv?q`
  - `GET /v1/admin/notifications/export.csv`
  - `GET /v1/audit-events/:stream/export.csv`
  - 응답 `text/csv; charset=utf-8` + `Content-Disposition: attachment` + **UTF-8 BOM**(Excel 한글), 행은 `for await` 스트리밍(전체 메모리 비적재 — 푸시다운 쿼리로 페이지 순회).
- 프론트: 각 목록 상단 "내보내기(CSV)" 버튼 → 현재 필터로 `window.location` 또는 fetch+blob 다운로드.
- **마스킹**: CSV에도 연락처 끝4자리·CI 미포함(기존 정책), viewer 역할 제외 또는 민감열 제거.
- **수용 기준**: 필터 적용된 전체 결과 CSV, 한글 Excel 정상, 마스킹 유지, 1만건+ 스트리밍 OK, 무권한 401.
- **규모**: M. **즉시 착수 가능(결정 불요)**.
- **리스크**: 민감정보 유출 → 마스킹·스코프·접근로그(actor) 기록. 대용량 응답 타임아웃 → 스트리밍·gzip.

## 2. P1 — 운영 효율·포용성

### P1-1. 웹 접근성 강화 (KWCAG 2.2 / WCAG 2.1 AA)
**근거**: 의료·공공 → 웹접근성 품질인증 대상 가능, 고령 환자가 포털 주 사용자. 현재 ARIA·키보드·focus 기본.

**구현 명세**:
- **포털(우선)**: 글씨 크기 토글(100/150/200%, localStorage 지속), 고대비 모드, 터치 타깃 ≥56px, 쉬운 언어(전문용어 풀이·툴팁), 단계 진행 `aria-live`, 상태를 색+아이콘+텍스트 3중 전달.
- **콘솔**: 스킵 네비 링크(`<a href="#main">`), **Modal 포커스 트랩**(현재 Esc·배경클릭만 — 진입 시 첫 포커스·Tab 순환·복귀), landmark roles(`<main>`/`<nav>`), 표 `<caption>`·정렬 헤더 `aria-sort`, 폼 onBlur inline 검증·`aria-describedby`.
- **토큰**: 고대비/확대 변형을 `tokens.css` 변수 세트로(다크모드와 동일 메커니즘 재사용).
- **검증 도구**: `@axe-core/playwright` 또는 `eslint-plugin-jsx-a11y` CI 게이트(회귀 방지).
- **수용 기준**: axe 위반 0(주요 화면), 키보드만으로 전 플로우 가능, 포털 200% 확대 시 레이아웃 깨짐 없음, 모달 포커스 트랩.
- **규모**: M(포털) + M(콘솔). **결정 불요**.

### P1-2. 일괄 작업(Bulk)
**근거**: 데이터 누적(확장성 작업과 짝). 현재 전부 개별 작업. 만료 임박 다건 발송·다건 폐기 수요.

**구현 명세**:
- 프론트: `Table.tsx`에 selectable 모드(행 체크박스·헤더 전체선택·선택 카운트 바). 선택 대상 일괄 액션 바(철회/발송/폐기). 위험 작업은 확인 모달 + 일괄 사유.
- 백엔드: 일괄 EP(`POST /v1/requests/bulk/withdraw {ids[], reason}` 등) 또는 프론트 병렬 호출 + 진행률(부분 실패 보고). RBAC(viewer 제외)·감사 actor 귀속.
- **수용 기준**: 다건 선택→일괄 처리·부분 실패 리포트, viewer 차단, 각 건 감사 기록.
- **규모**: M. **결정 불요**.
- **리스크**: 대량 위험작업 오조작 → 확인 모달·건수 명시·undo 불가 경고.

### P1-3. 운영 시각화(차트)
**근거**: 현재 통계는 숫자 카드뿐. 추세·분포 인사이트 부재.

**구현 명세**:
- 백엔드: 집계 EP `GET /v1/admin/metrics?from&to&bucket=day` — 일자별 요청 생성/완료/만료, 상태 분포, 인증서 발급량, **webhook 성공률**. 인덱스 컬럼(`reqCreatedAt`·`notBefore`·`status`)으로 DB `GROUP BY`(저비용). ops-status 5초 캐싱과 정합.
- 프론트: 경량 차트(의존성 최소 인라인 SVG 또는 `recharts`) — `/admin`·`/admin/system`에 추세 라인·상태 도넛·webhook 성공률 게이지.
- **수용 기준**: 기간 선택 시 시계열 렌더, 0건 빈상태, 대용량서 집계 일정 응답.
- **규모**: M.

## 3. P2 — UX 고도화 (선택) + 신규 발견 항목

### P2-1. 다크모드
토큰이 CSS 변수 → 다크 팔레트 변수 + `prefers-color-scheme` + 수동 토글(localStorage). 인쇄·매뉴얼 iframe 예외. **규모 S~M**. 접근성 고대비와 메커니즘 공유.

### P2-2. i18n (영어 우선)
한국어 전용 → `next-intl` 도입, 문자열 외부화(500+), 로케일 날짜/숫자. **규모 L**. **수요 발생 시**(EMR/외국인 환자).

### P2-3. 실시간 업데이트(SSE) — *백엔드 신규*
현재 수동 새로고침. `GET /v1/events/stream`(SSE, 관리자 인증) — 요청 상태 변경·webhook 결과·서명 진행 push. 대시보드/요청 상세 자동 갱신, 포털 다자 진행 표시. **규모 M~L**(백엔드 SSE 신규 + 프론트 구독 + 재연결).

### P2-4. 성능 — skeleton·가상 스크롤
로딩 skeleton(Spinner 대체), 큰 표 가상 스크롤. 단 푸시다운으로 페이지 일정 비용이라 가상 스크롤 우선순위 낮음. **규모 S~M**.

### P2-5. 시각적 서명 표식(드로잉/서명패드) — *결정 필요*
현재 서명은 본인확인+암호(PKI) 서명만, **시각적 handwritten 표식 없음**. 일부 동의 UX·환자 친숙도/심리적 수용을 위해 캔버스 서명패드를 추가하고 **감사인증서 PDF에 이미지 임베드** 가능. **단 법적 효력은 암호 서명이 담보 — 드로잉은 UX/인지 보강이지 법적 필수 아님**. 도입 시 이미지 PHI 보관 정책 고려. **규모 M · 우선순위 낮음(기획 판단)**.

### P2-6. 다탭 세션 동기화
idle 자동 로그아웃이 sessionStorage 기반 **탭별 독립** — 한 탭 로그아웃이 타 탭에 즉시 반영 안 됨(다음 요청 시 401로 정리됨). `BroadcastChannel`로 탭 간 로그아웃 브로드캐스트. **규모 S · 가치 낮음**.

### P2-7. 알림 센터 / 전역 에러 바운더리
- 인앱 알림 센터(webhook 실패·만료 임박·CA 회전 등 운영 이벤트 모음) — ops-status 폴링/ SSE 기반. **규모 M**.
- React Error Boundary 전역(예기치 못한 렌더 오류 시 친절한 폴백 + 리포트). **규모 S**.

### P2-8. 환자 포털 PWA
오프라인 안내·홈화면 추가·푸시(서명 요청 알림). 단 서명은 온라인 필수라 효용 제한적. **규모 M · 가치 중하**.

## 5. 수용 기준 / 성공 지표(예시)
- 포털 PDF: 서명 전 문서 열람률·해시검증 100%·만료 후 파기.
- CSV: 심사 제출 항목(서명활동·발급·접속기록) 1-클릭 내보내기·마스킹 0누락.
- 접근성: axe 위반 0(주요 화면)·키보드 전 플로우·포털 200% 확대.
- 차트: 운영 추세 가시화·webhook 성공률 모니터.

## 6. 오버엔지니어링 가드(하지 말 것)
- 가상 스크롤·복잡 상태관리(Redux 등)·마이크로프런트엔드: 현 규모·푸시다운 고려 시 **불필요**.

- 실시간(SSE): 폴링으로 충분한 화면에 과도 적용 금지(요청 상세·다자 진행만 가치).

## 7. 공통 원칙
- 기능 추가 시 **운영 매뉴얼 동반 갱신**(`web/manual.source.html`→`npm run manual:build`).
- 민감정보(CI·연락처)는 신규 표면(CSV·차트·PDF·드로잉)에서도 **마스킹·미저장** 유지.
- RBAC(viewer 읽기전용)·감사 actor 귀속·세션 보안(F004/2.6.3)과 정합.
- 디자인 토큰 단일 출처(다크/고대비/확대=토큰 변형). 접근성은 CI(axe) 게이트로 회귀 방지.
