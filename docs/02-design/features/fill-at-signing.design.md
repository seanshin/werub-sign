# fill-at-signing — 포털 서명자 입력란 직접 기재 설계 (백로그 A4)

- 상태: **v1.1 as-built — 권장안 B 구현(v1.13.0) + §5 미결 3건 확정·구현(v1.15.0, 2026-07-28)**. 마크 타입 명칭은 코드 기준 `FIELD`(설계 초안의 INPUT 표기 정정)
- 작성: 2026-07-27 · 구현: 2026-07-28(기본) · 고도화: 2026-07-28(입력 타입·박스 맞춤·증적 조회)
- 관련: `general-contracts.design.md`(§10 ④ 마커·배치), 손글씨 서명(§10 ⑤ — 본 설계의 기반 패턴)

## 1. 문제

현재 `[입력란#N:라벨]` 마커는 **작성자가 값을 기입**하고 위치만 표시한다. 실무 요구는 "외부 서명자가 포털에서 자기 몫의 입력란(계좌번호·주소·성명 등)을 직접 기재"인데, 문서를 기재값으로 바꾸면 **업로드 시점에 봉인된 서명 대상 해시(documentHash)가 깨진다**. 특히 순차 다자서명에서는 앞 서명자가 서명한 문서와 뒤 서명자가 보는 문서가 달라져 봉투 모델과 근본 충돌한다.

## 2. 옵션 비교

| 옵션 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A. 재조판·재해시 | 기재 라운드 종료 후 최종 PDF 재조판→새 해시로 전원 서명(2단계 상태기계) | 원본 PDF 자체에 값 포함 | 봉투 모델 대수술(기재 라운드 신설·해시 교체·중간 철회 처리), 규모 대 |
| **B. 기재값 별도 봉인+합성(권장)** | 원본 불변. 기재값을 **행위 증거로 암호화 저장+SHA-256 감사 봉인**, 표시본에 온더플라이 합성 | **손글씨 서명과 완전 동형**(검증된 파이프라인 재사용), 해시 봉인 원칙 무변경, 순차/동시 모두 자연 지원, 규모 소~중 | 원본 PDF엔 값 없음 — 합성 표시본이 실무 문서(손글씨와 동일, 이미 수용된 트레이드오프) |
| C. supersede 재발행 | 기재 확정 시 문서 개정 체인(C-2)으로 새 봉투 재발행 | 기존 개정 체인 재사용 | 기재마다 재발행·재발송(UX 나쁨), 서명 진행 중 불가 |

## 3. 권장안 B 상세

**원칙**: 손글씨 서명(csign)과 동형 — "PKI 서명=법적 효력, 기재값=행위 증거(감사 체인+TSA 봉인)".

- **데이터**: `ctfill:<requestId>:<participantId>` meta — `{ values: [{ markIndex, label, value }], sealed(SecretBox), sha256, filledAt }`. 값 자체는 암호화 보관, SHA-256 을 `CONTRACT_FILLED` 감사 이벤트로 체인 봉인.
- **입력란 배정**: 배치 편집기의 `INPUT` 마크에 서명자 순번이 이미 있음. **선행 수정**: 계약 생성 시 `signMarks` 저장이 `SIGN` 타입만 필터 → `INPUT` 도 저장(합성 좌표·배정 판정).
- **포털 흐름**: unlock→문서 확인→**본인 배정 입력란 폼 표시(라벨별 텍스트 입력, 필수)**→서명 제출 시 값 동봉(`POST /v1/portal/:token/sign` body 확장 `fillValues`) — 기재와 서명을 한 트랜잭션으로(별도 저장 EP 불요, fail-closed: 값 봉인 실패 시 서명 미수행).
- **합성 표시**: `renderSignedDocument` 확장 — 손글씨 합성과 동일 파이프라인에서 INPUT 마크 좌표에 기재값 텍스트 드로잉(나눔고딕). 관리자 상세·완료 교부본·공개 QR 검증본 모두 합성본.
- **검증·증거**: 감사추적인증서에 기재값 해시 포함. 서명검증 탭에 "기재값 봉인" 표시.
- **내부 서명자**: 콘솔 내부 서명 Modal에 동일 폼(선택 적용).

## 4. 수용 기준(안)

1. 외부 2인 순차: 각자 자기 입력란만 기재 가능, 타인 입력란 불가(403). 기재값 SHA-256 감사 봉인.
2. 원본 documentHash 불변 — verify overall=true 유지(전원 서명 후).
3. 완료 교부본·상세 표시본에 기재값 합성 렌더. 원본(raw=1)은 미합성.
4. 필수 입력란 미기재 시 서명 409. 서명 후 기재 수정 불가.
5. 백엔드 e2e(기재→서명→합성 pdftoppm/pdf.js 검증) + UI e2e(포털 폼→서명→상세 확인).

## 5. 확정 사항(v1.1, 2026-07-28 승인·구현 완료)

초안의 미결 3건은 사용자 승인으로 다음과 같이 확정·구현했다.

### 5.1 입력 형식 — 타입 4종

`PlacedMark.fieldType: 'text' | 'date' | 'money' | 'number'`(**미지정=text** — 기존 마크 하위호환). 서버가 형식을 검증하고 **정규화된 값**을 봉인·합성한다(정본=`ContractService.normalizeFieldValue`).

| 타입 | 허용 입력 | 정규화 | 길이 상한 | 위반 |
|---|---|---|---|---|
| text | 임의(제어문자 제거·연속 공백 축약) | trim | 200자 | 400 |
| date | `YYYY-MM-DD`·`YYYY.MM.DD`·`YYYY/MM/DD`·`YYYYMMDD` | `YYYY-MM-DD`(실재 일자 검사 — 2026-02-30 거부) | 10자 | 400 |
| money | 숫자·콤마·공백·`원` | 3자리 구분(`1,500,000`, 선행 0 제거) | 20자 | 400 |
| number | 정수·소수(부호 허용) | 콤마·공백 제거 | 20자 | 400 |

- 클라이언트(`web/src/lib/field-type.ts`)가 **같은 규칙으로 선검증** — 포털은 본인확인 단계 진입 전에 차단하고, 서버 400 이 나면 종료 화면 대신 기재 단계로 되돌린다. 판정 정본은 서버.
- 배치 편집기 팔레트에 타입 select, 포털·내부 폼은 타입별 placeholder·`inputMode`·maxLength 를 적용한다.

### 5.2 박스 초과 — 줄바꿈 → 축소 → 말줄임

`layoutFieldValue()`: ①어절 단위 줄바꿈(어절 자체가 폭 초과 시 글자 단위 분할 — 한글 주소 대응) → ②맞을 때까지 폰트 축소(11pt → 6pt, 0.5pt 단위) → ③6pt 에서도 넘치면 허용 줄 수까지만 그리고 마지막 줄 말줄임(`…`) + `warn` 로그(값은 로그에 남기지 않음 — 라벨·requestId 만). 줄 높이 배율 1.25, 박스 세로 중앙 정렬.

### 5.3 작성자 사전 기입값과의 공존

**현행 유지** — 작성자는 서식 `{{키}}`·본문 편집으로 값을 직접 채우고, **서명자 몫만 입력란(FIELD) 마크로 비워 둔다**. FIELD 마크가 곧 "서명자가 기재할 칸"의 단일 정의이며, 배정된 칸은 전량 필수(누락 409, fail-closed). 본문 마커 `[입력란#N:라벨]`(조판 표시 전용)은 타입 개념이 없으므로 text 로 취급한다.

### 5.4 기재값 증적 조회

`GET /v1/contracts/:id/fill-values`(`contracts:read`) — 서명자별 기재 원문·타입·봉인 SHA-256·기재 시각·경로(PORTAL/CONSOLE)·무결성 재검증 결과(`integrityOk`). 계약 상세 서명자 탭에 표시(손글씨 이미지와 같은 신뢰경계).

**규모(실적)**: 초안 추정대로 백엔드 소~중 + 프론트 중 + e2e. 손글씨 인프라 재사용.
